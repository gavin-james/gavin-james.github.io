# 博客正文写作规范（本轮完善专用）

> 适用于：`/Users/mac/Documents/code/front/gavin-james.github.io/src/` 下要重写/补齐的专题文档。
> 目的：把 20-40 行的「提纲」升级为**能当资料用的正文**，风格统一、可发布。

## 1. Frontmatter（统一用新式）

```md
---
title: Spring IoC 容器详解
category: [框架]
tag: [Spring, IoC]
---
```

- `title`：中文标题，与正文一级标题一致（不要 `# ` 与 title 重复成两句话）。
- `category`：单一分类，取值必须是本站已有分类之一：`Java 基础` `Java 集合` `Java 多线程` `Java IO` `Java 新特性` `Java JVM` `数据库` `NoSQL Redis` `NoSQL MongoDB` `NoSQL ElasticSearch` `开发` `设计模式` `算法` `框架` `架构` `前端` `工具`。
  本区一般固定：框架区用 `框架`；架构区用 `架构`；前端区用 `前端`；工具区用 `工具`。
- `tag`：2-4 个，具体技术名（如 `Spring` `IoC` `分布式锁`）。
- 不要在正文里再写一行 `title:` 或 `category:`。

## 2. 篇幅与结构

- **概念/原理类正文**：目标 **2500–5000 中文字符**（不含代码）。低于 1500 视为不合格。
- **总览/索引页**（`*/overview.md`、`README.md`）：1200–2500 字，用链接清单 + 简短导读。
- 推荐骨架（按内容取舍，不必全有）：

```
# 标题
> 一句话定位（这是什么、解决什么问题）

## 1. 为什么/背景（不这么做会怎样）
## 2. 核心概念与原理（配表格/图/流程）
## 3. 关键机制拆解（分小节讲深）
## 4. 代码/配置示例（可运行的 Java / YAML / 命令）
## 5. 实践要点与常见坑
## 6. 小结（3-6 条）
```

## 3. 语言与质量

- **简体中文**，技术准确，第三人称陈述，不写"我们""让我们一起"这类口水话。
- **禁止占位**：不得出现 `TODO` / `占位` / `敬请期待` / `待补充` / `TBD` / `WIP`。写不到的内容宁可删掉该小节，也不留空壳。
- **禁止照抄 pdai.tech 原文**（版权）。正文必须自己组织：可参考其知识结构，但用自己的话+标准示例写。结尾不必再贴"参考 pdai.tech"。
- **准确性第一**：只用你确知正确的 API / 配置 / 结论。不确定的具体字段名、版本号、参数，不要编；用通用表述或省略。
- 代码块必须能表达清楚意图且语法正确（Java 用 `java`，配置用 `yaml`/`bash`/`xml`）。
- 术语首次出现给英文全称，如"控制反转（Inversion of Control, IoC）"。

## 4. 可用的 Markdown 扩展（vuepress-theme-hope，已配置）

- 代码高亮：` ```java ` / ` ```yaml ` / ` ```bash ` / ` ```sql ` / ` ```xml `（支持行号）。
- 表格：标准 GFM 表格。
- 提示块：`::: tip 标题` / `::: warning` / `::: danger` / `::: important` / `::: note` / `::: info` / `::: details 折叠标题` … `:::`。
- 流程图：` ```mermaid ` 代码块。
- 数学：`$...$` 行内、`$$...$$` 块级（katex）。
- 标签页：`::: tabs` + `@tab 名称`。
- 站内链接：相对路径，如 `[分布式锁](./distributed-lock.md)`。

## 5. 站内跳转

- 用相对路径链接同区其它文档，帮助读者串联，例如：
  `见 [分布式事务](../distributed/distributed-transaction.md)`。
- 不要留死链：只链接你确认存在的文件（本区标题清单见各任务说明）。
