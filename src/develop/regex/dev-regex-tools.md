# 正则表达式工具与调试技巧

> 正则表达式写起来快、读起来难，稍不留神就会写错。本文汇总常用的在线工具与调试手段，帮助把"能匹配"与"匹配对"区分开，并给出常见场景的正则与 Java 中的用法。

## 1. 常用在线工具

| 工具 | 地址 | 特长 |
| --- | --- | --- |
| Regulex | https://jex.im/regulex | 把正则**可视化**成流程图，直观理解匹配路径 |
| Regex101 | https://regex101.com | 实时高亮匹配、解释每个分组，支持多种正则方言 |
| Regexr | https://regexr.com | 可视化 + 测试二合一，带常用表达式速查 |
| 菜鸟在线测试 | https://c.runoob.com/front-end/854 | 轻量、中文界面，快速验证 |

### 1.1 可视化理解（Regulex）

把表达式粘贴进 Regulex，会得到类似流程图的图形。以**正浮点数**为例：

```text
^[1-9]\d*\.\d*|0\.\d*[1-9]\d*|0?\.0+|0$
```

图形会清楚展示"整数部分允许的几种分支"，远比盯着字符猜结构高效。适合用它检查括号与 `|` 的优先级——很多错误其实是分支范围写错。

### 1.2 在线测试（Regex101 / 菜鸟）

这类工具能：

- 实时高亮命中的文本，验证是否**多匹配**或**漏匹配**；
- 逐组解释每个 `()` 捕获的内容；
- 列出 `\d \w \s`、量词、断言等元字符含义。

写完后务必**用边界样例实测**：空串、超长串、含特殊字符的串都要覆盖。Regex101 还支持切换 Java / JavaScript / Python 等方言，因为不同语言对 `\d`、回顾后发断言的实现存在差异。

## 2. 调试技巧

- **从简到繁**：先写能匹配核心子串的最小正则，再逐步加锚点与量词，避免一次性堆出复杂表达式。
- **锚定边界**：需要整串匹配时加 `^` 和 `$`，否则 `find` 会在子串上匹配成功而"看起来对"。
- **警惕贪婪量词**：`.*` 默认贪婪，会吞掉过多内容；用 `.*?` 惰性匹配，或提高分隔符的精确度。
- **区分匹配与校验**：`Pattern.matches` / `^...$` 用于整串校验，`find` / `search` 用于提取子串。
- **注意转义**：在 Java 字符串里 `\d` 要写成 `"\\d"`，这是最常见的低级错误。
- **性能意识**：嵌套量词（如 `(a+)+`）会造成**灾难性回溯**，处理不可信输入时可能被拖垮，可用占有量词或原子组缓解。

::: warning 不要在循环里反复编译
`Pattern` 的编译有成本。应把 `Pattern.compile(...)` 的结果缓存为常量或静态字段，仅在需要时创建 `Matcher`。
:::

## 3. Java 中的使用

```java
import java.util.regex.Matcher;
import java.util.regex.Pattern;

public class RegexDemo {
    // 编译一次，复用
    private static final Pattern EMAIL =
            Pattern.compile("^[\\w.-]+@[\\w.-]+\\.[A-Za-z]{2,}$");

    public static boolean isValidEmail(String s) {
        return EMAIL.matcher(s).matches();     // 整串匹配
    }

    public static void findAll(String text) {
        Matcher m = Pattern.compile("\\d+").matcher(text);
        while (m.find()) {                      // 提取子串
            System.out.println(m.group());
        }
    }
}
```

常用 API：

- `Pattern.compile(regex, flags)`：编译，`flags` 可设 `CASE_INSENSITIVE`、`MULTILINE`、`DOTALL` 等；
- `Matcher.matches()`：整串匹配；`find()`：查找下一个；`group(n)`：取第 n 个捕获组；`replaceAll(repl)`：替换。

## 4. Java 高级特性

掌握以下特性可以写出更精确、更高效的正则：

- **捕获组与反向引用**：`(\w+)\s+\1` 匹配两个重复的单词，`\1` 引用第一个组；
- **命名分组**：`(?<year>\d{4})-(?<month>\d{2})`，用 `m.group("year")` 取值，可读性更好；
- **非捕获组**：`(?:...)` 只分组不捕获，减少不必要的捕获开销；
- **零宽断言**：`(?=...)` 先行、`(?<=...)` 后行，只做条件判断不消耗字符，例如 `(?<=\$)\d+` 匹配金额数字；
- **批量替换**：`Matcher.appendReplacement` / `appendTail` 配合，按组动态替换。

```java
// 反向引用：把重复单词替换为一个
"hello hello world".replaceAll("(\\b\\w+\\b)\\s+\\1", "$1");
// 结果："hello world"
```

::: danger 灾难性回溯与 ReDoS
形如 `(a+)+$` 的嵌套量词在匹配失败时会尝试指数级组合，攻击者可用特制输入令 CPU 满载（ReDoS）。防范手段：避免嵌套量词、用占有量词 `a++` 或原子组 `(?>...)`、限制输入长度，必要时改用不支持回溯的引擎（如 RE2/J）。
:::

## 5. 常用表达式速查

> 完整清单见 [常用正则表达式](./dev-regex-usage.md)，知识点见 [正则表达式知识点](./dev-regex-all.md)。

| 场景 | 表达式 |
| --- | --- |
| 手机号（中国大陆） | `^1[3-9]\d{9}$` |
| 邮箱 | `^[\w.-]+@[\w.-]+\.\w{2,}$` |
| 身份证（18 位） | `^\d{17}[\dXx]$` |
| 正浮点数 | `^[1-9]\d*\.\d*\|0\.\d*[1-9]\d*\|0?\.0+\|0$` |
| IPv4 | `^((25[0-5]\|2[0-4]\d\|1\d\d\|[1-9]?\d)\.){3}(25[0-5]\|2[0-4]\d\|1\d\d\|[1-9]?\d)$` |
| 中文字符 | `^[\u4e00-\u9fa5]+$` |
| 日期（YYYY-MM-DD） | `^\d{4}-\d{2}-\d{2}$` |
| 金额（两位小数） | `^\d+(\.\d{1,2})?$` |

::: important 正则不是万能的
邮箱、URL 等格式用严格正则校验往往过度复杂且仍不完美，实践中通常"用宽松正则粗筛 + 业务逻辑精校验"。别为了写一个"绝对正确"的邮箱正则而陷入维护地狱。
:::

## 6. 小结

- 用 Regulex / Regex101 / Regexr 等工具**可视化 + 实测**，能发现大部分书写错误。
- 调试遵循"从简到繁、锚定边界、警惕贪婪量词"，并注意 Java 字符串的双反斜杠转义。
- 善用捕获组、命名分组、零宽断言写精确的正则；缓存 `Pattern`，避免循环内编译。
- 警惕灾难性回溯带来的 ReDoS 风险，必要时使用 RE2/J 等无回溯引擎。
- 常见格式优先查现成表达式，但宽松校验往往比"完美正则"更实用。
- Java 中区分 `matches`（整串）与 `find`（子串搜索）的语义。
